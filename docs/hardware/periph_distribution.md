# Распределение периферии по модулям (ESP32 / Arduino Nano)

Статус: **актуализирован** (уточнение ролей последовательных клапанов; заслонка/насосы полов — через RS485-устройства).  
Источник правды: `rnd/peripherals.md`. Основано на `docs/architecture/modules.md`, `AGENTS.md`, `rnd/plan.txt`.

## Принципы распределения
- **Безопасность превыше всего.** Критичные датчики/контуры защиты назначаются с приоритетом на независимость модуля безопасности (Nano).
- **Два уровня защиты.** ESP32 несёт основную нагрузку управления, Nano — супервизор с независимыми контурами отключения и safety-gate.
- **Последовательные клапаны (NC).** На подачу масла и на подачу воздуха — по 2 клапана последовательно. **`*_VALVE_MAIN` — рабочие (ESP32)**, **`*_VALVE_SAFETY` — защитные/safety-gate (Nano)**. Nano открывает safety-клапаны только при безопасных условиях; при аварии/потере связи закрывает их через независимые контуры (fail-safe). ESP32 управляет **только 2 из 4** клапанов.
- **Fail-safe.** При потере связи/аварии приоритет за независимыми контурами Nano.
- **RS485-актуаторы.** `ACT_DAMPER_ACTUATOR`, `ACT_PUMP_FLOOR_1/B` управляются устройствами на шине RS485 (ESP32 — мастер). Прямые GPIO для них не выделяются.
- **Решения не гадать.** Там, где требуется доработка схемы/пин-мапа — помечено соответствующе.

## 2. Датчики и измерительные приборы

### 2.1. Безопасность и контроль горения (горелка)

## 3. Связь, сервисные функции, хранение

| Элемент | ESP32 | Arduino Nano (Safety) | Обоснование |
|---|---|---|---|
| **Связь ESP32<->Nano** | **Активный участник (обмен командами/телеметрией/heartbeat)** | **Активный участник + супервизор (heartbeat, алармы, fail-safe)** | Базово — **выделенный point-to-point UART** (рекомендация, см. `docs/architecture/modules.md`). Nano контролирует heartbeat и инициирует защитные действия. |
| **RS485 (доп. устройства)** | **Только ESP32 (мастер)** | **Не используется** | Для модулей тёплых полов, заслонки, доп. периферии. Управление `ACT_DAMPER_ACTUATOR`, `ACT_PUMP_FLOOR_1/B` — через RS485-устройства. Сбой RS485 **не должен** обходить защиту горелки. |
| **Детект пропадания питания сети 220В** | **ESP32** | **Наблюдение/информирование (при наличии)** | Детект назначается **ESP32**. Данные передаются Nano по выделенному каналу связи; независимые контуры Nano не ослабляются. Способ детекта определяется при проработке схемы. |
| **Перезагрузка ESP32** | — | **Возможно по решению Nano (аппаратный RESET)** | Инициируется только Nano при потере связи/подозрении на зависание. Независимые контуры отключения горелки остаются активными (safety-gate закрыт). |
| **Коды ошибок, уровни угрозы, хранение в памяти** | **Оба модуля (сохранение при аварии)** | **Оба модуля (сохранение при аварии)** | Единый протокол ошибок. При переходе в аварийное состояние каждый модуль обязан сохранить код ошибки с уровнем угрозы в энергонезависимую память (EEPROM/Flash) для постфактум-анализа. Детали в `docs/protocol/errors.md` (планируется), определения в `include/common_protocol.h`. |

## Опциональный вариант: FPC (контур подготовки топлива)

Статус: **не принят**, анализ зафиксирован в `docs/architecture/modules.md`. При рассмотрении варианта FPC:
- `SEN_OIL_TEMP_SAFETY`, `SEN_FLOAT_MIN/MAX` остаются **прямо подключёнными к Nano** (основной контроль безопасности). Перенос только на FPC запрещён.
- `ACT_HEATER_OIL`: прикладное управление (ПИД) может быть у FPC/ESP32, но Nano обязан иметь **независимый аппаратный аварийный cutoff** (обход невозможен).
- `ACT_PUMP_OIL_TRANSFER`: прикладная логика может быть у FPC/ESP32, но Nano обязан иметь **независимый аппаратный безопасный путь блокировки/останова** по уровням/защите (fail-safe default OFF). Иные варианты — только после анализа отказов/схемы и отдельного `APPROVE` `safety-reviewer`.
- Связь с FPC: при внедрении предпочтителен **гибрид** (аппаратный safety-gate от Nano + RS485 телеметрия/команды). Безопасность не опирается только на FPC/RS485. Fail-safe при потере связи/неопределённости.
- Любая реализация — только после схемы `schematic-engineer` и ревью `safety-reviewer`.

## Краткие выводы по ключевым требованиям
- **Клапаны масло/воздух (по 2 последовательно):** `ACT_*_VALVE_MAIN` — рабочие, **ESP32**; `ACT_*_VALVE_SAFETY` — safety-gate, **Nano** (открытие при OK, независимое закрытие при аварии, fail-safe NC). ESP32 управляет только 2 из 4 клапанов. ✓
- **Давление воздуха (`SEN_AIR_PRESSURE`)** — Nano (основной контроль для независимой защиты). ✓
- **Пламя (`SEN_FLAME`)** — ESP32 (ведущий для FSM). ✓
- **Температура выхлопа (`SEN_THERMOCOUPLE_K`)** — **решение отложить до шага 3 (пин-мап)**. ✓
- **ТЭН, вентилятор, зажигание** — с учётом независимых контуров Nano (приоритетные контуры отключения). ✓
- **Заслонка/насосы тёплых полов** — **через RS485-устройства** (без прямых GPIO). ✓
- **RS485** — только ESP32 (мастер доп.устройств). ✓
- **Дублирующее управление насосом котла (`ACT_PUMP_BOILER`)** — опция за Nano. ✓
- **Детект пропадания питания** — ESP32. ✓
- **Коды ошибок, хранение в памяти** — оба модуля. ✓
