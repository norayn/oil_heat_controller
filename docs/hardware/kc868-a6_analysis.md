# KinCony KC868-A6 (не v3) — анализ платы как Main Unit

Статус: **принята условно (safety-gated)** как целевая плата Main Unit; **pinmap/схема НЕ утверждены**, board-level верификация **не выполнена**.
Дата: 2026-11-09
Роль: **Main Unit (ESP32)** — замена NodeMCU V3 / ESP32 DevKit baseline.
Что плата **не заменяет**: **Safety Unit (Arduino Nano)** и его независимые аппаратные контуры отключения.

> Пин-мап здесь **не фиксируется**. Любое назначение выводов — только кандидат до записи в `docs/hardware/pinmap.md` (шаг 3) и board test.
> Смена версии платы (A6v3 → A6) **не является approval** и **не закрывает** BLK-002/003/005/006/007/008/009/010.
> Внутренняя схема A6 **официально доступна** (`KC868-A6-schematic.pdf`), но её применимость к конкретной ревизии платы подтверждается визуально/измерением.

## 0. Краткое резюме

KC868-A6 (не v3) — плата того же класса, что A6v3, но на **ESP32-WROOM-32** (не ESP32-S3). Для проекта это означает:

1. **Внутренняя схема доступна официально** — можно подтвердить тип контактов реле, драйвер, опто-входы, RS485/RS232, питание. Это **снижает board-level неопределённость** по сравнению с A6v3, схема которого недоступна. **Но** схема всё равно требует сверки с фактической ревизией платы.
2. **MCU — ESP32 (WROOM-32), не S3.** Меньше GPIO/памяти, нет native USB (стоит **CH340C**), нет octal PSRAM N16R8. Для задач Main Unit (координация, FSM, UART, I2C, ADC) — достаточно, но **проверить flash/PSRAM по маркировке**.
3. **Управление I/O — PCF8574 по I2C** (реле `0x24`, входы `0x22`), как и у v3. Это **не независимый/fail-safe safety path**; безопасность остаётся за внешним слоем Nano.
4. **Публичная схема не закрывает** внешние силовые/защитные цепи проекта (BLK-002 и др.) — они проектируются отдельно.

**Вердикт:** принять как Main Unit **с ограничениями** — при выполнении условий §6, board-level верификации §7 и approvals `schematic-engineer` + `safety-reviewer`. Как безусловная замена — **нет**.

## 3. Сопоставление с требованиями проекта

### 3.1. Что плата даёт
- 6 реле (прикладное управление актуаторами) + 6 опто-входов.
- 4 АЦП (кандидат под `SEN_FLAME` — **только при BLK-005 APPROVE**).
- 2 канала 1-Wire (DS18B20).
- RS485 (non-safety доп.устройства, S-49), RS232.
- I2C (PCF8574, опц. OLED/RTC).
- DAC 0–10 В (заслонка — non-safety).

### 3.2. Чего плата не даёт
- **Не fail-safe safety path:** реле/входы на PCF8574/I2C (latch/reset/brownout/I2C fault). Nano остаётся единственным safety-слоем.
- **Нет native USB** — прошивка/отладка через CH340.
- **Меньше памяти/GPIO**, чем S3 N16R8 — проверить достаточность (flash/PSRAM).

### 3.3. Бюджет I/O Main Unit
Ресурсов для координации достаточно, **при условии** что критические датчики остаются на Nano и не занимают KC868. Конкретное распределение — `pinmap.md` (DRAFT).

## 4. Ключевые риски (те же, что у линейки A6)

1. **PCF8574/I2C — единый домен отказа.** Реле сохраняют последнее состояние при reset/зависании MCU. Нельзя опираться на «выключено по умолчанию».
2. **Драйвер ULN2003A + PCF8574:** поведение при POR/просадке 3,3 В — подтвердить измерением (слабая подтяжка ≠ гарантированный OFF).
3. **RS485 без гальваноизоляции** — не использовать для safety-связи; для non-safety — TVS/терминирование по схеме.
4. **ADC A3/A4** — режим (0–5 В vs 4–20 мА) подтвердить; не использовать для voltage-сигнала пламени без валидации.
5. **GPIO strapping** (0/2/5/12/15) — не назначать без проверки boot-поведения.
6. **Питание/бросок тока** при board-off/on (SR-B6) — измерить.

| Питание | **XL1509-5.0 → LM1117-3.3** | Ток, бросок, тепловой режим |
| ADC A1/A2 | Делители 0–5 В | Точность/шум |

## 6. Обязательные условия принятия (safety-gated)

1. **Safety Unit Nano не заменяется.** Все Nano-инварианты сохраняются:
   - `ACT_OIL_VALVE_SAFETY`, `ACT_AIR_VALVE_SAFETY` (NC) — **только Nano**;
   - `SEN_AIR_PRESSURE`, `SEN_OIL_TEMP_SAFETY`, `SEN_FLOAT_MIN/MAX` — **прямые на Nano**;
   - SR-B4/SR-B18 — только подтверждённой схемой;
   - fail-safe/latch/no auto-resume.
2. **PCF8574/I2C — только прикладное управление** при Nano hardware safety-gate/cutoff/block-stop. Внутренности платы **не считаются safety-гарантией**.
3. **Dedicated point-to-point UART** Nano↔Main Unit, не RS485.
4. **Внешние силовые/защитные цепи** (BLK-002 контактор/ТЭН/розжиг/подкачка, SR-B6 power-cycle, BLK-007 насос, S-48 монтаж) — проектируются отдельно, схема платы их **не закрывает**.
5. **`SEN_FLAME` (BLK-005)** — остаётся **PROPOSED/NOT VALIDATED**; A6-АЦП требует переподтверждения каналов/диапазонов/шума; fallback SR-B13/S-47.
6. **Протокол (BLK-006)** — до `safety-reviewer` APPROVE не реализовывать в прошивке.
7. **Pinmap остаётся DRAFT / NOT APPROVED** до board test + approvals.

> **Важно:** «принять условно» **≠ approval** pinmap/схемы/прошивки/протокола и **не ослабляет** gates в `docs/architecture/blockers.md`.

- [ ] Маркировка модуля: **ESP32-WROOM-32**, flash/PSRAM; статус GPIO0/1/3 и UART0↔CH340C routing.

- [ ] RS485 MAX13487EESA: терминирование 120 Ом/bias, DE/RE, TVS, помехоустойчивость; изоляции нет — зафиксировать.

- [ ] Тепловой режим платы в котельной (XL1509/LM1117/реле).
