# Граница безопасности FSM / принятый риск: температура выхлопа (BLK-003)

Статус: **DOC READY — требуется `safety-reviewer` ACK** (не утверждает схему/прошивку).  
Связанный блокер: `docs/architecture/blockers.md` → **BLK-003 (HIGH, ACCEPTED RISK, REQUIRES ACK)**.  
Дата: 2026-11-08.

## Решение / граница ответственности

`SEN_THERMOCOUPLE_K` + MAX6675 (температура выхлопных газов, если используется) — **технологическая обратная связь процесса горения Main Unit (KC868/ESP32)**. Это **не зона независимого контроля Nano Safety**.

- Nano **не имеет** независимого hardware-триггера/отсечки по перегреву выхлопа.
- Температура выхлопа **не является** независимым Nano safety interlock.
- Документ **не** заявляет эквивалент независимого Nano thermal cutoff по выхлопу.

## Что остаётся обязательным (Nano-инварианты, не ослабляются)

Защита от опасных режимов горелки/топливоподачи опирается на Nano:

- `ACT_OIL_VALVE_SAFETY` / `ACT_AIR_VALVE_SAFETY` — **NC safety-gates, только Nano**, независимые контуры, fail-safe закрыты.
- `SEN_AIR_PRESSURE` — **прямой вход Nano**, независимая защита (нет/недостаточно давления => топливо не подаётся / опасные действия запрещены по Nano-политике).
- `SEN_OIL_TEMP_SAFETY`, `SEN_FLOAT_MIN`, `SEN_FLOAT_MAX` — **прямые входы Nano**.
- Heartbeat + semantic supervision (`fsmState`/`stateAge`/счётчики, `I2C_FAULT`/протокольная валидность), `safetyPermit`/gate/latch/sensorValid semantics (BLK-006, draft).
- Независимые Nano hardware paths: общий Nano-контактор (не самозамыкающийся, управляется только Nano) для `ACT_HEATER_OIL`/`ACT_PUMP_OIL_TRANSFER`/`ACT_IGNITION_UNIT` при подтверждённой схеме (SR-B4/SR-B18/BLK-002), SR-B6 supervised power-cycle KC868 (только Nano, last resort) — без ослабления safety-gates/cutoffs.
- Fail-safe, **latch**, **запрет авто-возобновления** опасных режимов без безопасных условий/продувки/проверок и явной политики подтверждения.

## Обязательное поведение Main Unit (FSM) — для реализации/ревью

При использовании `SEN_THERMOCOUPLE_K`/MAX6675:

1. **Валидность обязательна для опасных действий, где FSM это требует.** Недостоверность, timeout, fault/open/short MAX6675, `NaN`/out-of-range, отсутствие обновления, SPI/CRC/диагностическая ошибка => трактовать как **невалидную обратную связь**.
2. **Невалидная обратная связь => безопасный прикладный режим.** Main Unit **не продолжает** опасный розжиг/не подтверждает устойчивое горение/не продолжает опасную работу без валидной обратной связи там, где FSM требует подтверждения процесса. Переход по FSM в безопасное состояние: прекращение подачи топлива/закрытие рабочих команд, безопасный останов/постпродувка по политике, запрет повторного опасного пуска до восстановления валидности и безопасных предусловий.
3. **Fail-safe по умолчанию.** Любая неопределённость в цепочке датчика/формирователя/чтения/алгоритма = консервативное решение (не «огонь есть/температура нормальная»).
4. **Latch/ограничение рестарта** — по политике FSM и только при подтверждённых безопасных условиях; Nano latch/`safetyPermit` не обходятся.
5. **Диагностика/телеметрия** — фиксировать fault/timeout/invalid для логов/NVM/heartbeat (без ослабления защиты). Реализация heartbeat/полей — только после BLK-006 `safety-reviewer` APPROVE.

## Требуемый ACK

`safety-reviewer` должен явно подтвердить (**ACK**):

- принятие границы «выхлоп — технологическая обратная связь Main Unit, не Nano safety interlock»;
- достаточность компенсирующих Nano-инвариантов для данного этапа/конфигурации;
- отсутствие ослабления SR-B4/SR-B18/safety-gates/прямых Nano датчиков/fail-safe/latch/no auto-resume;
- условия пересмотра при изменении требований к защите от перегрева выхлопа, изменении компоновки/топки/материалов, или появлении независимого датчика/триггера на Nano.

## Пересмотр обязателен, если

- пользователь/схема/FSM требуют независимой аппаратной защиты от перегрева выхлопа;
- появляется прямой Nano датчик/триггер выхлопа или меняется роль Nano;
- меняются режимы горения/топливо/мощность/материалы дымохода/топки так, что принятый риск недопустим.
