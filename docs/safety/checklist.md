# Чек-лист ревью по безопасности

**Обязателен для `safety-reviewer` при ЛЮБЫХ правках кода в `src_esp32/` и `src_avr8/`, а также при правках `include/` и конфигурации.**

Безопасный код нужен в ОБОИХ модулях. Ревью не ограничивается только Safety Unit.

## 1. Общие принципы
- [ ] **Fail-safe** — при потере связи/неопределённом состоянии реализован переход в безопасное состояние
- [ ] **Приоритет защиты** — логика безопасности не ослаблена, Safety Unit сохраняет финальное право запрета
- [ ] **Детерминизм** — в Safety Unit нет блокирующих конструкций там, где критична скорость реакции
- [ ] **Минимум изменений** — не сделано "лишних" правок в критичном коде
- [ ] **Соответствие спецификации** — правка согласуется с `rnd/peripherals.md`

## 2. Модуль розжига и горелки (критично)
- [ ] **Контроль пламени** (`SEN_FLAME`) — **baseline SR-B13/S-47 (обязателен):** Main Unit, только **direct ESP32-S3 GPIO + внешний гальванически изолированный формирователь digital/Schmitt**; запрещено opto/PCF8574/I2C/ADC-raw. Fail-safe полярность/диагностика, max latency end-to-end, потеря пламени => latch/no auto-restart. **BLK-005 отклонение (фоторезистор->аналоговый вход KC868)** — **PROPOSED/NOT VALIDATED, НЕ разрешено к реализации** до PASS ЭМС/схемной валидации и `safety-reviewer`+`schematic-engineer` APPROVE; при fail/нестабильности обязательный fallback на SR-B13/S-47.
- [ ] **Давление воздуха** (`SEN_AIR_PRESSURE`) — **прямо на Nano**, проверка перед подачей топлива и во время работы
- [ ] **Последовательность розжига** — корректная, с таймаутами на каждый этап; Nano супервизия по heartbeat/`fsmState`/`stateAge`
- [ ] **Таймауты розжига** — жёсткий таймаут, по истечении -> блокировка + безопасное отключение
- [ ] **Safety-gate клапаны** (`ACT_OIL/AIR_VALVE_SAFETY`) — **только Nano**, независимые контуры, NC fail-safe, обход Main Unit невозможен
- [ ] **Рабочие клапаны** (`ACT_OIL/AIR_VALVE_MAIN`) — прикладное управление Main Unit (KC868 relay допустим условно) **только при Nano safety-gates в силовой/гидравлической цепи**
- [ ] **Зажигание** (`ACT_IGNITION_UNIT`) — в группе Nano-контактора (fail-safe) или эквивалентной Nano блокировке; включение только по разрешению/таймаутам
- [ ] **Вентилятор наддува** (`ACT_FAN_BLOWER`) — **в обход общего Nano-контактора** (для продувки). Требуется режимный safety-анализ (purge vs emergency stop), решение по независимому Nano cutoff или обоснованный отказ; без `safety-reviewer` APPROVE — **блокер**.

## 3. Преднагрев масла, уровни, температуры (критично)
- [ ] **Поплавки** (`SEN_FLOAT_MIN/MAX`) — критический минимум блокирует работу, максимальный уровень блокирует подкачку
- [ ] **Температура масла** (`SEN_OIL_TEMP_MAIN`, `SEN_OIL_TEMP_SAFETY`) — защита по перегреву реализована
- [ ] **Термопара дымовых газов** (`SEN_THERMOCOUPLE_K` + MAX6675) — защита по перегреву, обработка обрыва/короткого
- [ ] **Подогрев ТЭНом** (`ACT_HEATER_OIL`) — с ограничениями по температуре
- [ ] **Подкачка масла** (`ACT_PUMP_OIL_TRANSFER`) — не в обход защит, с контролем уровней

## 4. Связь Main Unit (KC868/ESP32) <-> Safety Unit (критично)
- [ ] **Dedicated point-to-point UART** — не общая RS485 для safety-связи (без отдельного обоснования+`safety-reviewer` APPROVE)
- [ ] **Heartbeat** — 100–200 мс, timeout ≤3 периодов (≤600 мс), обе стороны
- [ ] **`protoVer`/`seq`/CRC** — валидация, обработка битых/stale/replay/несовместимых пакетов => fail-safe
- [ ] **Явное разрешение Nano** — `safetyPermit`/`gateState`/`alarmBits`/`latch`/`sensorValid`; отсутствие/невалидность = safe state Main Unit
- [ ] **Здоровье Main Unit** — `fsmState`/`stateAge`/`fsmCycle`/`i2cPollCycle`/`i2cStatus` (+ статус пламени/розжига, достаточный для супервизии Nano); семантическое застревание детектируется (SR-B8/B11/B12/B16)
- [ ] **`I2C_FAULT` при живом heartbeat** — Nano применяет fail-safe политику (не считать Main Unit полностью управляющим KC868 path)
- [ ] **Потеря связи/permit != разрешение на работу** — обе стороны fail-safe, latch, без авто-возобновления опасных режимов
- [ ] **`include/common_protocol.h`** — `TelemetryPacket` = non-safety draft; миграция только с `safety-reviewer` APPROVE

## 5. Код обоих модулей
- [ ] **src_avr8/** — детерминизм, минимум абстракций, явные проверки
- [ ] **src_esp32/** — не пытается обходить защиту, корректно обрабатывает статус от Safety Unit
- [ ] **include/common_protocol.h** — изменения обоснованы, обратная совместимость учтена или версия протокола повышена
- [ ] **platformio.ini** — изменения не ломают мульти-окружение

## 6. Финальная проверка
- [ ] **Все таймауты на месте** — розжиг, продувка, связь
- [ ] **Все клапаны в безопасном состоянии при ошибке/стопе**
- [ ] **Критичные проверки есть** — их нельзя закомментировать/убрать
- [ ] **Изменение не ослабляет защиту** — явное обоснование если кажется спорным
- [ ] **Протестировано логически** — продуманы типичные сбои (обрыв связи, потеря пламени, падение давления воздуха)

**Решение:** `APPROVE` / `REQUEST_CHANGES` / `BLOCK` (при ослаблении защиты)
