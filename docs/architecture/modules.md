# Разделение ответственности Main Unit (KC868-A6) / Safety Unit (Nano)

Статус: **актуализирован** — архитектурное решение: **KinCony KC868-A6, не v3 (ESP32-WROOM-32, USB-C + CH340C, DIN/12В, 6 реле PCF8574 `0x24`, 6 опто-входов PCF8574 `0x22`, 4×ADC, 2×1-Wire, RS485, RS232)** используется как **Main Unit** (замена NodeMCU V3/ESP32 DevKit baseline). Принятие **safety-gated/условно** и требует выполнения обязательных условий `docs/hardware/kc868-a6_analysis.md` §6, закрытия SR/S замечаний (SR-B4/B6/B8/B12–B18, S-47/48/49; **SR-B10 пересмотрен решением пользователя** — см. ниже), **board-level verification §7 (официальная схема A6 + пин-лист/даташиты/измерение)**, board test и повторного ревью `schematic-engineer` + `safety-reviewer`. **Nano не заменяется.** Сохранены: safety-gate клапаны, независимые Nano cutoffs/block-stop, UART-vs-RS485 для safety-связи, RS485-актуаторы (non-safety), fail-safe/NVM/severity, FPC опционально.

**Решение пользователя (текущее):** PCF8574 I/O KC868 **не является независимым/fail-safe safety path** (latch/reset/brownout/I2C fault). Onboard реле/входы допустимы **только для прикладного управления/технологических сигналов** и **только при обязательных независимых Nano hardware safety-gate/cutoff/block-stop в силовых цепях**. Nano имеет приоритет и финальное право блокировки/обесточивания; это **аппаратный** backup, не программный fallback. Входы KC868 — только **технологические/не safety-критичные**; `SEN_AIR_PRESSURE`, `SEN_OIL_TEMP_SAFETY`, `SEN_FLOAT_MIN/MAX` — прямые на Nano. `SEN_FLAME` — **BLK-005 PROPOSED/NOT VALIDATED** (фоторезистор->аналоговый вход KC868 + ЭМС-тесты; fallback opto/изолированный формирователь на direct ESP32 GPIO); SR-B13/S-47 требования не сняты, требуется `safety-reviewer`+`schematic-engineer` APPROVE.

**Блокеры/открытые проблемы:** см. `docs/architecture/blockers.md` (BLK-001…011). До закрытия CRITICAL/HIGH — step 3 pinmap/schematic, protocol implementation/migration, firmware: **BLOCK**.

## Общие принципы

- **Main Unit (KC868-A6, ESP32-WROOM-32)** — координирует котёл, теплоаккумулятор, циркуляционные контуры и прикладные процессы. Несёт прикладную логику безопасной работы горелки, но **не является независимым контуром защиты**. Onboard I/O KC868 (реле/опто-входы через PCF8574 по общей I2C вместе с RTC/OLED/DAC) **само по себе не fail-safe**: PCF8574 без RESET может хранить состояние; поведение реле при сбросе/зависании ESP32, brownout/просадке 3.3В, потере питания/инициализации драйвера **не гарантировано**. **Принятое решение:** PCF8574 I/O KC868 считается **условно безопасным для прикладного управления при подстраховке Nano**. Это означает:
  - **Onboard реле KC868** допускается использовать для **прикладного (рабочего) управления актуаторами** там, где это возможно/целесообразно, **только при наличии обязательных независимых Nano hardware safety-gate/cutoff/block-stop в силовых цепях** (SR-B4, SR-B18, safety-gates, ignition blocking по схеме). KC868 relay **не заменяет** Nano cutoff/safety-gate и **не является независимым путём аварийной отсечки**. Риск latch/reset/`I2C_FAULT` компенсируется Nano (heartbeat/I2C health, forced-off policy, supervised power-cycle SR-B6, независимые силовые контуры).
  - **Onboard опто-входы/ADC/GPIO ресурсы KC868** допускается использовать для **технологических/не safety-критичных датчиков и сигналов**. `SEN_AIR_PRESSURE`, `SEN_OIL_TEMP_SAFETY`, `SEN_FLOAT_MIN/MAX` остаются **прямо на Nano** (инвариант). `SEN_FLAME` — **BLK-005 PROPOSED/NOT VALIDATED** (фоторезистор->аналоговый вход KC868 + экранирование + ЭМС-тесты при розжиге; fallback opto/изолированный формирователь на direct ESP32 GPIO). Отклонение от SR-B13/S-47; до валидации/APPROVE не утверждать. `SEN_THERMOCOUPLE_K` (выхлоп) — технологическая обратная связь горения, **не зона контроля Nano Safety** (BLK-003, ACCEPTED RISK, ACK req.).
  - Любое использование KC868 I/O для нагрузок/сигналов, влияющих на безопасность, требует подтверждения силовой схемы, fail-safe поведения, Nano backup и `safety-reviewer` (+ `schematic-engineer`).
- **Safety Unit (Arduino Nano)** — независимый супервизор/модуль безопасности. Следит за heartbeat/здоровьем Main Unit, контролирует аварии по своим датчикам, имеет **независимые аппаратные контуры отключения/блокировки** (safety-gate клапаны, series cutoff ТЭН SR-B4, hardware block/stop подкачки SR-B18, независимая блокировка розжига и др. по схеме), и может инициировать **supervised, last-resort, current-limited power-cycle 12В KC868** (SR-B6). Nano **не отсекает собственное питание** и не заменяется.
- **Два уровня безопасности.** Безопасный код в ОБОИХ модулях. Nano обладает аппаратно-независимыми путями принудительного отключения; Main Unit не может их обойти.
- **Fail-safe.** При потере связи, ошибке протокола/CRC/seq/`protoVer`, `I2C_FAULT`, зависании FSM/семантическом застревании, сбоях, авариях Nano, потере разрешения или неопределённости — горелка/опасные актуаторы в безопасное состояние.
- **Последовательные клапаны (NC).** На подачу масла и на подачу воздуха — **по 2 последовательно соединённых NC-клапана**. `ACT_*_VALVE_MAIN` — рабочие, прикладное управление Main Unit через внешние модули; `ACT_*_VALVE_SAFETY` — safety-gate, **управляются только Nano** через независимые контуры. Nano открывает safety-клапаны только при подтверждённо безопасных условиях и валидном разрешении; при аварии/потере heartbeat/неопределённости/латче принудительно закрывает (fail-safe). Main Unit **не имеет возможности обхода**.
- **Критичные решения не принимаются на предположениях.** UART/RS485, пин-мап, grounding/isolation (§7.18), supervised power-cycle key/feedback (SR-B6), общий Nano-контактор/feedback/weld (BLK-002), `SEN_FLAME` схема+ЭМС-валидация (BLK-005), монтаж 220В/транзиенты (S-48), MAX6675 placement/диагностика — фиксируются при схеме/пин-мапе и проходят `safety-reviewer` (+ `schematic-engineer` где применимо).

## Распределение ответственности

### Main Unit (KC868-A6, ESP32-WROOM-32) — `src_esp32/` (`env:esp32_core`, `board = esp32dev`)

Полное прикладное управление процессами системы. Основные прикладные нагрузки безопасной работы горелки — на Main Unit, но **финальная аппаратная блокировка/отсечка** — за Nano.

**Управление горелкой и розжигом:**
- **FSM горелки/котла** — розжиг, прогрев, стабилизация, работа, останов, постпродувка; жёсткие max-таймауты состояний, `fsmState`/`stateAge` для heartbeat (SR-B16); heartbeat формируется в цикле FSM, не в отдельном «живом» таймере (SR-B8/B11/§7.8). TWDT подписан на задачу FSM.
- **Прикладное управление актуаторами горелки/котла** — команды FSM для `ACT_IGNITION_UNIT`, `ACT_OIL_VALVE_MAIN`, `ACT_AIR_VALVE_MAIN`, `ACT_FAN_BLOWER`, `ACT_HEATER_OIL` (через внешний SSR/драйвер), `ACT_PUMP_OIL_TRANSFER`, `ACT_PUMP_BOILER` (по утверждённой политике). Управление `ACT_OIL_VALVE_SAFETY`/`ACT_AIR_VALVE_SAFETY` **не входит** в обязанности Main Unit. Любое действие может быть принудительно заблокировано/обесточено Nano через независимые контуры.
- **`ACT_HEATER_OIL` (ТЭН):** прикладное управление (ПИД/ограничения) — Main Unit через **внешний** SSR/драйвер. **Обязательно:** Nano имеет **независимый механический контактор/силовой контакт в силовой цепи последовательно с ТЭН** (SR-B4), плюс аппаратный термостат/термопредохранитель и предохранители по схеме. SSR **не** является средством аварийного отключения.
- **`ACT_PUMP_OIL_TRANSFER`:** прикладная логика — Main Unit (и/или FPC только если опционально принят); допускается прикладное управление через onboard реле KC868 **только как условно безопасное при подстраховке Nano**. **Обязательно:** Nano имеет **независимый аппаратный block/stop в силовой цепи насоса**, fail-safe default **OFF** (SR-B18). На KC868 onboard relay как на средство безопасного останова опираться нельзя.
- **Контроль хода розжига/пламени (BLK-005, PROPOSED/NOT VALIDATED)** — `SEN_FLAME`: по решению пользователя фоторезистор на **аналоговый вход KC868** (экранированный кабель) + практические тесты наводок при розжиге; при недостаточности — опторазвязка/внешний изолированный формирователь (digital/Schmitt) на **direct ESP32 GPIO**. Это **отклонение от SR-B13/S-47** (запрет ADC-raw) — требуется валидация: fail-safe пороги/гистерезис/debounce/диагностика, обрыв/КЗ/потеря питания/`saturated/stuck` = «нет пламени», PASS/FAIL тесты ЭМС при розжиге, `safety-reviewer`+`schematic-engineer` APPROVE. До валидации реализация не утверждена. Потеря/недостоверность пламени => консервативный режим, закрыть топливо, постпродувка/безопасный останов по FSM, latch/no auto-restart. Nano супервизия: heartbeat + `fsmState/stateAge` + `flameStatus` + собственные датчики + safety-gates.
- **Организация безопасности на уровне FSM** — проверки, блокировки, защитные переходы (основной прикладной уровень). Весь код Main Unit проектируется по fail-safe.

**Теплоаккумулятор и гидравлика:**
- **ТА** — `SEN_TEMP_TA_IN/OUT`, циклы нагрев/отдача.
- **Котловой контур** — контроль `SEN_TEMP_BOILER_IN/OUT/CORE`. **`ACT_PUMP_BOILER` политика (SR-B17, §7.15, BLK-007):** Nano-дублирование **не является опцией по умолчанию**. Управление/питание насоса котла — по **утверждённой** схеме: отдельное некоммутируемое питание + термо/гидрозащита **или** подтверждённый безопасный выбег + температурная защита. Прикладное управление через onboard реле KC868 допустимо только как **не safety-путь** при утверждённой политике; Nano не обеспечивает по умолчанию дублирующий аппаратный контур. Отказ запуска/потеря управления => контролируемая остановка по политике, без хаотичного перегрева.
- **Подкачка масла** — `ACT_PUMP_OIL_TRANSFER` с учётом Nano hardware block/stop и прямых уровней Nano.
- **Насосы тёплых полов (перспектива)** — `ACT_PUMP_FLOOR_1`, `ACT_PUMP_FLOOR_B` **только через RS485-slave устройства**. Прямых GPIO нет.
- **Дымовая заслонка (перспектива)** — `ACT_DAMPER_ACTUATOR` **только через RS485-slave устройство**. Прямого GPIO нет.

**Связь и координация:**
- **Обмен с Safety Unit** — dedicated point-to-point UART (см. `docs/protocol/uart.md`), heartbeat, телеметрия, команды/запросы по протоколу, приём `safetyPermit`/gate/latch/alarm/sensorValid. KC868: **USB-C + CH340C** — debug/прошивка (не native USB); safety UART — на свободных GPIO (TBD шаг 3, board test/официальный пин-лист). При потере валидного разрешения/heartbeat от Nano — немедленный safe state, latch, запрет авто-возобновления.
- **RS485 доп.устройства (non-safety)** — ESP32 мастер. **S-49:** DMX512-compatible и Modbus — **отдельные RS485 сегменты/шины**; строгие runtime limits `DE/RE`, таймауты, abort/flush; 1-Wire и RS485 не в safety-path (DMX lighting исключён из fail-safe критериев). Сбой RS485 **не влияет** на защиту горелки.
- **Мониторинг/диагностика** — агрегирование состояний, I2C/PCF8574 health, ошибок; индикация (OLED/сеть — по возможности, не safety).
- **Планировщик** — циклы отопления.

### Safety Unit (Arduino Nano) — `src_avr8/`

Независимый супервизор. Контролирует Main Unit и аварии по своим датчикам. Имеет собственные независимые контуры отключения/блокировки и может выполнять supervised power-cycle KC868.

**Супервизия Main Unit:**
- **Мониторинг по протоколу** — heartbeat, `seq`/`protoVer`/CRC, `fsmState`/`stateAge`/`fsmCycle`/`i2cPollCycle` (монотонные счётчики, переполнение по модулю), I2C/PCF8574 health, состояния критичных актуаторов (SR-B8/B11/B12/B16, §7.8). Heartbeat 100–200 мс, таймаут ≤3 периодов (≤600 мс) — норматив фиксируется в `docs/protocol/uart.md` и `include/common_protocol.h` (миграция).
- **Таймаут/невалидность/семантическое застревание** — отсутствие приращения счётчиков, `I2C_FAULT`, битый пакет, недопустимый `fsmState`/`stateAge`, потеря связи => немедленный fail-safe Nano (safety-gate закрыт, опасные контуры в safe state), latch.
- **Оценка работоспособности** — анализ статуса Main Unit; право принудительного safe state независимо от команд.
- **Supervised power-cycle KC868 (SR-B6)** — только Nano, **last resort**, через выделенный внешний силовой ключ 12В KC868: current-limited/soft-start по схеме, **без fast cycling**, min off-time ≥10 с (или обоснованный), лимит попыток, 3-state feedback `KC868_12V present/absent/fault-unknown`, forced OFF KC868 relays по возможности до цикла, re-enable только после safe preconditions, latch при залипании/несостоявшейся отсечке. Nano **не отсекает своё питание** (отдельный некоммутируемый 5В ≥1А; холдап только для фиксации/логирования). Залипание контакта ≠ безопасная отсечка; safety-gate/контактор ТЭН — последняя линия. Процедуры прошивки Nano при D0/D1/UART — в pinmap/schematic.
- **Аппаратный RESET Main Unit** (если реализуется отдельно от power-cycle) — только через изолированный/определённый ключ по схеме; не заменяет power-cycle/fail-safe.

**Управление защитными клапанами (safety-gate):**
- **`ACT_OIL_VALVE_SAFETY`, `ACT_AIR_VALVE_SAFETY`** — только Nano, собственные независимые контуры, NC fail-safe. Открытие только при безопасных условиях и валидном состоянии; немедленное закрытие при аварии/потере связи/латче/неопределённости. Приоритет Nano абсолютен. Гидравлика NC / электрическая реализация (energize-to-permit/de-energize-to-trip, тип контакта/драйвера) — по схеме (§6.1 KC868 analysis как ориентир; подтвердить на шаге 3).

**Независимые контуры отключения/блокировки (минимум, по схеме):**
- Независимое управление safety-gate клапанами топлива/воздуха.
- **Общий Nano-контактор / силовое реле группы (решение пользователя, упрощение схемы):** Nano управляет **независимым силовым контактором/силовым реле** (**не самозамыкающимся, без схемы самоподхвата; по сути мощное силовое реле, управляемое только Nano**), через который подаётся питание на **`ACT_HEATER_OIL` (ТЭН подогрева), `ACT_PUMP_OIL_TRANSFER` (насос подкачки), `ACT_IGNITION_UNIT` (блок розжига)**. **`ACT_FAN_BLOWER` (вентилятор наддува) питается в обход этого контактора** (решение пользователя). Управление **только Nano**, независимо от Main Unit/KC868; fail-safe: при аварии, потере heartbeat, latch, reset/brownout/неопределённости Nano — **обесточивание/размыкание** по SR-B14/B15/схеме (поведение при Hi-Z/bootloader подтверждается). «Не самозамыкающийся» **не снимает** weld/non-trip/single-point/feedback требования (BLK-002 design gate).
  - Реализует/усиливает независимый аппаратный cutoff для перечисленных нагрузок и соответствует целям SR-B4 (`ACT_HEATER_OIL`, силовая цепь последовательно с ТЭН; SSR не средство аварийного отключения) и SR-B18 (`ACT_PUMP_OIL_TRANSFER`, hardware block/stop fail-safe OFF), **при условии подтверждённой схемой реализации** (расположение в силовых цепях, номиналы, отсутствие шунтирования, сохранение термозащиты ТЭН/предохранителей).
  - **Вентилятор (в обход контактора, BLK-001, ACCEPTED DESIGN):** `ACT_FAN_BLOWER` управляется KC868 relay; Nano может **обесточить всю плату KC868** (SR-B6, coarse) => реле сбрасываются; плюс защитный автомат. **Независимый per-circuit Nano cutoff не требуется** (решение пользователя): продолжение работы вентилятора в аварии не считается критичным (электрозащита автоматом; продувка тёплым воздухом — не safety-critical). Топливная/горелочная безопасность: **Nano safety-gates** (топливо/воздух), **`SEN_AIR_PRESSURE`** Nano (нет давления => топливо не подаётся), обесточивание `ACT_HEATER_OIL`/`ACT_PUMP_OIL_TRANSFER`/`ACT_IGNITION_UNIT` контактором. SR-B6 board-off — аварийный side effect (убивает Main Unit/FSM/heartbeat); схема/автомат — `schematic-engineer`+`safety-reviewer`.
  - Номиналы, категория контактора (AC-1/AC-3 и т.п.), inrush, ЭМС от розжига, селективность, 220В проводка/изоляция — `schematic-engineer` + `safety-reviewer`.
- **`ACT_PUMP_BOILER`** — Nano-дублирование **не по умолчанию** (SR-B17). Любой защитный путь — только утверждённая схема/политика питания.
- **Nano fail-safe outputs (SR-B14/SR-B15):** energize-to-permit / de-energize-to-trip где применимо; определённые уровни выходов при reset/brownout/bootloader; Hi-Z = de-energized; внешние pull-down/pull-up по схеме; WDT включён; brownout/отпускание катушек/общий внешний watchdog по §5.7/§7.11 KC868 analysis — **обязательные схемные условия**.

**Контроль по своим датчикам (критичная защита):**
- **`SEN_AIR_PRESSURE`** — пороговый, основной контроль Nano для независимой защиты.
- **`SEN_OIL_TEMP_SAFETY`** — DS18B20, аварийная отсечка ТЭН/защита (прямое подключение к Nano).
- **`SEN_FLOAT_MIN`, `SEN_FLOAT_MAX`** — герконы, прямое подключение к Nano; контроль «на сухую», перелив/подкачка, hardware block/stop подкачки.

**Критичные датчики не переносятся на FPC/RS485/PCF8574.**

**Безопасный код в Nano:** минимальный, предсказуемый, детерминированный; без неоправданных `delay()`; таймауты, WDT; быстрые критичные реакции.

## Размещение датчиков горения/давления/температуры выхлопа

- **`SEN_AIR_PRESSURE`** — Nano (независимая защита). ✓ Инвариант.
- **`SEN_FLAME`** — **Main Unit (KC868)**, **PROPOSED / NOT VALIDATED (BLK-005)**. Решение пользователя: фоторезистор на **аналоговый вход KC868**, экранированный кабель + практические тесты наводок при розжиге; при недостаточной помехоустойчивости — **опторазвязка/внешний изолированный формирователь (digital/Schmitt) на direct ESP32 GPIO**. **Отклонение от SR-B13/S-47** (ранее: только direct GPIO + внешний изолированный формирователь; запрещено ADC-raw). До валидации обязательно: fail-safe пороги/гистерезис/debounce, обрыв/КЗ/потеря питания/`saturated/stuck` = «нет пламени», PASS/FAIL тесты ЭМС при розжиге, `safety-reviewer`+`schematic-engineer` APPROVE. Nano прямого входа пламени не имеет; супервизия по heartbeat + `fsmState/stateAge` + `flameStatus` (BLK-006) + собственные датчики + safety-gates.
- **`SEN_THERMOCOUPLE_K` + MAX6675 (температура выхлопа)** — **Main Unit (KC868), технологическая обратная связь процесса горения (BLK-003, ACCEPTED RISK, требует `safety-reviewer` ACK)**. **Не зона контроля Nano Safety**: Nano не имеет независимого hardware-триггера перегрева выхлопа. Main Unit при недостоверности/timeout/fault обязан переходить в безопасный прикладный режим по FSM. Явно зафиксировать границу ответственности в FSM/safety spec.

## Анализ UART vs RS485 для связи Main Unit <-> Nano

Базовый вариант — **выделенный point-to-point UART**. KC868 предоставляет **USB-C + CH340C** для debug (не native USB) и свободные GPIO-кандидаты для UART (board test/официальный пин-лист, шаг 3); Nano D0/D1 конфликтуют с USB-программированием/отладкой — требуется процедура/переключение/альтернатива в pinmap. Общая RS485 для safety-связи **не рекомендуется** без отдельного обоснования, доказательства fail-safe при всех отказах шины/устройств и `safety-reviewer` APPROVE.

| Критерий | Выделенный UART (рекомендован) | Общая RS485 |
|---|---|---|
| Детерминизм/изоляция отказов | Высокая, отдельный канал | Ниже, зависит от мастера/устройств/шины |
| Fail-safe | Проще доказать | Сложнее (dominant fault, bus-off, конфликты) |
| Помехоустойчивость/дальность | Ниже RS485 (нужна развязка/уровни) | Выше, но избыточно для safety point-to-point |
| Вывод | **Предпочтителен для safety** | Только доп.устройства non-safety; для Nano — исключение после анализа+ревью |

## RS485 для дополнительных устройств (Main Unit)

- **Master-slave, ESP32 мастер**, адресация, CRC, таймауты/повторы, версионирование.
- Управляет `ACT_DAMPER_ACTUATOR`, `ACT_PUMP_FLOOR_1/B` через slave. **Прямых GPIO нет.**
- **S-49:** DMX512-compatible и Modbus — **раздельные сегменты/шины**. Runtime limits `DE/RE`, timeouts, abort/flush. 1-Wire/RS485 — non-safety (DMX lighting вне fail-safe критериев).
- **Fail-safe на slave (обязательно):** safe state при потере мастера/таймауте/некорректных данных/watchdog/fault/power loss. `ACT_PUMP_FLOOR_*` обычно OFF; `ACT_DAMPER_ACTUATOR` — безопасная позиция (`docs/protocol/rs485.md`). Собственный watchdog/tаймаут на slave.
- Сбой RS485 **не влияет** на защиту горелки.

## Детект пропадания питания сети (Main Unit)

- Детект на **Main Unit (KC868)**. Смысл при питании от ИБП; иначе потеря питания может обесточить плату.
- Антидребезг/гистерезис, подтверждённые пороги потери/восстановления.
- Реакция: фиксировать событие (NVM/лог), информировать Nano по UART; ограничение/управляемая остановка/запрет пуска по FSM+UPS-политике **без ослабления Nano**. Длительная потеря/ограниченное резервное питание — безопасный/ограниченный режим. Неопределённость — консервативно.
- Nano **не зависит** от этого сигнала для базовой отсечки. NC/fail-safe клапанов/драйверов/реле/Nano при пропадании сети/UPS — подтверждается схемой и `safety-reviewer`.

## Протокол ошибок (сводка)

- Единый протокол, уровни severity (CRITICAL/HIGH/MEDIUM/LOW), авария => сохранение кода в NVM до/при fail-safe в обоих модулях. Детали — `docs/protocol/errors.md` (планируется), определения/миграция — `include/common_protocol.h` с `safety-reviewer`.
- CRITICAL: немедленная отсечка Nano/safe state. HIGH: защитные действия, возможный supervised reboot/power-cycle (только Nano, SR-B6), safe state при невосстановлении.

## Опциональный вариант: FPC (Fuel Peripheral Controller)

Статус: **не принят**. Если рассматривать — **только гибрид**: аппаратный safety-gate от Nano + RS485 телеметрия/команды; safety не опирается только на FPC/RS485.
- Nano сохраняет прямые `SEN_OIL_TEMP_SAFETY`, `SEN_FLOAT_MIN/MAX`.
- Nano сохраняет **независимый аппаратный series cutoff `ACT_HEATER_OIL`** (SR-B4).
- Nano сохраняет **независимый аппаратный block/stop `ACT_PUMP_OIL_TRANSFER`, fail-safe OFF (SR-B18)**.
- Потеря связи/зависание FPC/неопределённость => fail-safe (ТЭН OFF, подкачка OFF). Любая реализация — схема + `safety-reviewer`.

## Важные замечания

- **Nano — независимый Safety Unit, не заменяется.** KC868 — Main Unit **условно** (§7).
- **KC868 onboard реле/PCF8574/I2C — не safety path.** I2C fault живёт отдельно от «живого» heartbeat (SR-B8); health в heartbeat (SR-B12).
- **`SEN_FLAME`** — BLK-005 PROPOSED/NOT VALIDATED (фоторезистор->аналоговый вход KC868, ЭМС-тесты; fallback opto/изолированный формирователь direct GPIO). До `safety-reviewer`+`schematic-engineer` APPROVE не утверждать.
- **Hardware paths:** heater series cutoff (SR-B4), pump transfer block/stop (SR-B18), safety-gates, ignition blocking — силовые/независимые.
- **220В монтаж/изоляция/транзиенты (S-48):** DIN вне отсека котла, IP/clearance/creepage, подавление транзиентов (варистор/snubber/RC) согласовано с предохранителями/MCB/RCD type A 30mA, NO-контакты по схеме; ratings подтверждаются.
- **Grounding/isolation architecture (§7.18)** — выбрать до схемы (A/B), не смешивать барьеры; фиксировать в pinmap/схеме.
- **`safety-reviewer`** — обязательный ревью **всех** правок кода в `src_esp32/`, `src_avr8/`, `include/` (особенно `common_protocol.h`), протокола, конфигурации, пин-мапа/силовой логики.
