# Разделение ответственности Main Unit (KC868-A6) / Safety Unit (Arduino Nano)

Статус: **актуально**. Main Unit — **KinCony KC868-A6, ревизия v1.3** (ESP32-WROOM-32, USB-C + CH340C, DIN/12 В, 6 реле через PCF8574 `0x24`, 6 опто-входов через PCF8574 `0x22`, 4×ADC, 2×1-Wire, RS485). Плата принята — `docs/hardware/kc868-a6_analysis.md` §6/§7, BLK-012. **Safety Unit — Arduino Nano (ATmega328P), не заменяется.** Pinmap/схема пока DRAFT: сверяются с реальной платой по ходу отладки.

> **Границы документа:** роли, принципы и границы ответственности. Владение конкретной периферией по кодам — `docs/hardware/periph_distribution.md`; физические линии/пины — `docs/hardware/pinmap.md`; бюджет линий A6 — `docs/hardware/kc868-a6_connection_plan.md`; открытые технические вопросы — `docs/architecture/blockers.md`; принятые риски — `docs/safety/accepted_risks.md`.

## Общие принципы

- **Main Unit (KC868-A6, ESP32-WROOM-32)** — координирует котёл, теплоаккумулятор, циркуляционные контуры и прикладные процессы. Несёт прикладную логику безопасной работы, но **не является независимым контуром защиты**.
- **PCF8574/I2C KC868 — не независимый/fail-safe safety path** (latch, reset, brownout, просадка 3,3 В, `I2C_FAULT`). Onboard реле/опто-входы допустимы **только для прикладного управления и технологических сигналов** и **только при обязательных независимых Nano hardware safety-gate/cutoff/block-stop в силовых цепях**. Nano имеет приоритет и финальное право блокировки/обесточивания — это **аппаратный** backup, не программный fallback.
- **Safety Unit (Arduino Nano)** — независимый супервизор: heartbeat/здоровье Main Unit, аварии по своим датчикам, **независимые аппаратные контуры** отключения/блокировки (safety-gates, series cutoff ТЭН SR-B4, block/stop подкачки SR-B18, блокировка розжига), supervised last-resort power-cycle 12 В KC868 (SR-B6). **Nano не отсекает собственное питание и не заменяется.**
- **Два уровня безопасности.** Безопасный код в ОБОИХ модулях. Nano обладает аппаратно-независимыми путями принудительного отключения; Main Unit не может их обойти.
- **Fail-safe.** При потере связи, ошибке протокола (`CRC`/`seq`/`protoVer`), `I2C_FAULT`, зависании FSM/семантическом застревании, сбоях, аварии Nano, потере разрешения или неопределённости — горелка и опасные актуаторы в безопасное состояние: latch, без авто-возобновления опасных режимов.
- **Последовательные клапаны (NC).** На подачу масла и воздуха — **по 2 последовательно соединённых NC-клапана**. `ACT_*_VALVE_MAIN` — рабочие, прикладное управление Main Unit; `ACT_*_VALVE_SAFETY` — safety-gate, **управляются только Nano** через независимые контуры. Nano открывает safety-клапаны только при подтверждённо безопасных условиях и валидном разрешении; при аварии/потере heartbeat/неопределённости/латче принудительно закрывает. Main Unit **не имеет возможности обхода**.
- **Критичные решения не принимаются на предположениях.** Пин-мап, grounding/isolation (§7.18), supervised power-cycle (SR-B6), общий Nano-контактор/feedback/weld (BLK-002), `SEN_FLAME` (BLK-005), монтаж 220 В/транзиенты (S-48), MAX6675 — фиксируются схемой/pinmap и проходят `safety-reviewer` (+ `schematic-engineer` где применимо).

## Main Unit (KC868-A6, ESP32-WROOM-32) — `src_esp32/`, `env:esp32_core`

Полное прикладное управление процессами системы. Основные прикладные нагрузки — на Main Unit, но **финальная аппаратная блокировка/отсечка — за Nano**.

**Горелка и розжиг:**
- **FSM горелки/котла** — розжиг, прогрев, стабилизация, работа, останов, постпродувка; жёсткие max-таймауты состояний, `fsmState`/`stateAge` для heartbeat (SR-B16); heartbeat формируется в цикле FSM, не в отдельном «живом» таймере (SR-B8/B11/§7.8). TWDT подписан на задачу FSM.
- **Прикладные команды** для `ACT_IGNITION_UNIT`, `ACT_OIL_VALVE_MAIN`, `ACT_AIR_VALVE_MAIN`, `ACT_FAN_BLOWER`, `ACT_HEATER_OIL` (через внешний SSR/драйвер), `ACT_PUMP_OIL_TRANSFER`, `ACT_PUMP_BOILER`. Управление `ACT_OIL_VALVE_SAFETY`/`ACT_AIR_VALVE_SAFETY` **не входит** в обязанности Main Unit. Любое действие может быть принудительно заблокировано/обесточено Nano.
- **`ACT_HEATER_OIL`:** прикладное управление (ПИД/ограничения) через **внешний SSR/драйвер**. Nano имеет **независимый механический контактор/силовой контакт в силовой цепи последовательно с ТЭН** (SR-B4), плюс аппаратный термостат/термопредохранитель и предохранители. SSR **не** является средством аварийного отключения.
- **`ACT_PUMP_OIL_TRANSFER`:** прикладная логика — Main Unit; допускается управление через onboard реле KC868 **только как условно безопасное при подстраховке Nano**. **Обязательно:** Nano имеет **независимый аппаратный block/stop в силовой цепи насоса, fail-safe OFF** (SR-B18). Onboard реле KC868 не является средством безопасного останова.
- **`SEN_FLAME`** — **BLK-005 PROPOSED/NOT VALIDATED**: фоторезистор на аналоговый вход KC868 + экранирование + ЭМС-тесты при розжиге; fallback — изолированный формирователь digital/Schmitt на direct GPIO. Отклонение от SR-B13/S-47; пока не проверено на котле, действуют требования baseline SR-B13/S-47. Потеря/недостоверность пламени => закрыть топливо, безопасный останов/постпродувка, latch/no auto-restart. Nano прямого входа пламени не имеет; супервизия — heartbeat + `fsmState/stateAge` + `flameStatus` + собственные датчики.
- **Безопасность на уровне FSM** — проверки, блокировки, защитные переходы. Весь код Main Unit проектируется fail-safe.

**Теплоаккумулятор и гидравлика:**
- **ТА** — `SEN_TEMP_TA_IN/OUT`, циклы нагрев/отдача.
- **Котловой контур** — `SEN_TEMP_BOILER_IN/OUT/CORE`. **`ACT_PUMP_BOILER` (SR-B17, §7.15, BLK-007):** политика по **утверждённой** схеме — отдельное некоммутируемое питание + термо/гидрозащита **или** подтверждённый безопасный выбег. Nano-дублирование **не является опцией по умолчанию**; отказ управления => контролируемая остановка без хаотичного перегрева.
- **Подкачка масла** — с учётом Nano hardware block/stop и прямых уровней Nano.
- **Насосы тёплых полов, дымовая заслонка (перспектива)** — **только через RS485-slave устройства**; прямых GPIO нет.

**Связь и координация:**
- **Обмен с Safety Unit** — dedicated point-to-point UART (`docs/protocol/uart.md`): heartbeat, телеметрия, команды/запросы, приём `safetyPermit`/gate/latch/alarm/sensorValid. При потере валидного разрешения/heartbeat — немедленный safe state, latch, запрет авто-возобновления.
- **RS485 (non-safety)** — ESP32 мастер. **S-49:** DMX512-compatible и Modbus — **раздельные сегменты/шины**; строгие runtime limits `DE/RE`, таймауты, abort/flush. Сбой RS485 **не влияет** на защиту горелки.
- **Мониторинг/диагностика** — агрегирование состояний, I2C/PCF8574 health, ошибок; индикация/сеть — по возможности, не safety.
- **Планировщик** — циклы отопления.

## Safety Unit (Arduino Nano) — `src_avr8/`, `env:arduino_safety`

Независимый супервизор. Контролирует Main Unit и аварии по своим датчикам, имеет собственные независимые контуры отключения/блокировки и может выполнять supervised power-cycle KC868.

**Супервизия Main Unit:**
- **Мониторинг по протоколу** — heartbeat, `seq`/`protoVer`/CRC, `fsmState`/`stateAge`/`fsmCycle`/`i2cPollCycle` (монотонные счётчики, переполнение по модулю), I2C/PCF8574 health, состояния критичных актуаторов (SR-B8/B11/B12/B16, §7.8). Heartbeat 100–200 мс, таймаут ≤3 периодов (≤600 мс) — норматив в `docs/protocol/uart.md` и `include/common_protocol.h`.
- **Таймаут/невалидность/семантическое застревание** — отсутствие приращения счётчиков, `I2C_FAULT`, битый пакет, недопустимый `fsmState`/`stateAge`, потеря связи => немедленный fail-safe (safety-gate закрыт, опасные контуры в safe state), latch.
- **Право принудительного safe state** независимо от команд Main Unit.
- **Supervised power-cycle KC868 (SR-B6)** — только Nano, **last resort**, через выделенный внешний силовой ключ 12 В: current-limited/soft-start, **без fast cycling**, min off-time ≥10 с (или обоснованный), лимит попыток, 3-state feedback `present/absent/fault-unknown`, forced OFF реле KC868 по возможности, re-enable только после safe preconditions, latch при залипании/несостоявшейся отсечке. Nano **не отсекает своё питание** (отдельный некоммутируемый 5 В ≥1 А; холдап — только для фиксации/логирования). Залипание контакта ≠ безопасная отсечка.
- **Аппаратный RESET Main Unit** (если реализуется отдельно от power-cycle) — только через изолированный/определённый ключ; не заменяет power-cycle/fail-safe.

**Safety-gate клапаны:**
- **`ACT_OIL_VALVE_SAFETY`, `ACT_AIR_VALVE_SAFETY`** — только Nano, собственные независимые контуры, NC fail-safe. Открытие только при безопасных условиях и валидном состоянии; немедленное закрытие при аварии/потере связи/латче/неопределённости. Приоритет Nano абсолютен. Гидравлика NC / электрическая реализация (energize-to-permit / de-energize-to-trip, тип контакта/драйвера) — по схеме.

**Независимые контуры отключения/блокировки (минимум, по схеме):**
- **Общий Nano-контактор / силовое реле группы:** **не самозамыкающееся, без самоподхвата, управляется только Nano**, без шунтирования/дублирующих путей. Через него питаются **`ACT_HEATER_OIL`, `ACT_PUMP_OIL_TRANSFER`, `ACT_IGNITION_UNIT`**. **`ACT_FAN_BLOWER` — в обход** (BLK-001 ACCEPTED DESIGN). Реализует/усиливает SR-B4 и SR-B18 **только при подтверждённой схеме**; не снимает weld/non-trip/feedback требования (BLK-002 design gate).
- **`ACT_PUMP_BOILER`** — Nano-дублирование **не по умолчанию** (SR-B17); любой защитный путь — только утверждённая схема/политика.
- **Nano fail-safe outputs (SR-B14/SR-B15):** energize-to-permit / de-energize-to-trip где применимо; определённые уровни при reset/brownout/bootloader; Hi-Z = de-energized; внешние pull-down/pull-up по схеме; WDT включён; brownout/отпускание катушек/внешний watchdog — обязательные схемные условия.

**Контроль по своим датчикам (критичная защита):**
- **`SEN_AIR_PRESSURE`** — пороговый, основной контроль Nano (нет/недостаточно давления => топливо не подаётся).
- **`SEN_OIL_TEMP_SAFETY`** — DS18B20, аварийная отсечка ТЭН (прямое подключение к Nano).
- **`SEN_FLOAT_MIN`, `SEN_FLOAT_MAX`** — герконы, прямое подключение к Nano; «на сухую», перелив/подкачка, hardware block/stop подкачки.

**Критичные датчики не переносятся на RS485/PCF8574.**

**Безопасный код в Nano:** минимальный, предсказуемый, детерминированный; без неоправданных `delay()`; таймауты, WDT; быстрые критичные реакции.

## Связь Main Unit ↔ Safety Unit: UART vs RS485

Базовый вариант — **выделенный point-to-point UART**. KC868: **USB-C + CH340C** — debug/прошивка (не native USB); safety UART — на свободных GPIO (кандидаты и board test — `docs/hardware/pinmap.md`, `docs/hardware/kc868-a6_connection_plan.md`). Nano D0/D1 конфликтуют с USB-программированием/отладкой — требуется процедура/переключение/альтернатива. Общая RS485 для safety-связи **не рекомендуется** без отдельного обоснования и доказательства fail-safe при всех отказах шины/устройств.

| Критерий | Выделенный UART (рекомендован) | Общая RS485 |
|---|---|---|
| Детерминизм/изоляция отказов | Высокая, отдельный канал | Ниже, зависит от мастера/устройств/шины |
| Fail-safe | Проще доказать | Сложнее (dominant fault, bus-off, конфликты) |
| Помехоустойчивость/дальность | Ниже RS485 (нужна развязка/уровни) | Выше, но избыточно для safety point-to-point |
| Вывод | **Предпочтителен для safety** | Только доп.устройства non-safety; для Nano — исключение после анализа+ревью |

## RS485 для дополнительных устройств (Main Unit)

- **Master-slave, ESP32 мастер**, адресация, CRC, таймауты/повторы, версионирование. Протокол — `docs/protocol/rs485.md`.
- Управляет `ACT_DAMPER_ACTUATOR`, `ACT_PUMP_FLOOR_1/B` через slave. **Прямых GPIO нет.**
- **S-49:** DMX512/Modbus — раздельные сегменты; runtime limits `DE/RE`, timeouts, abort/flush. 1-Wire/RS485 — non-safety.
- **Fail-safe на slave обязателен:** безопасное состояние при потере мастера/таймауте/некорректных данных/watchdog/fault/power loss. Сбой RS485 **не влияет** на защиту горелки.

## Детект пропадания питания сети (Main Unit)

- Детект на **Main Unit (KC868)**; смысл — при питании от ИБП; иначе потеря питания может обесточить плату.
- Антидребезг/гистерезис, подтверждённые пороги потери/восстановления.
- Реакция: фиксировать событие (NVM/лог), информировать Nano по UART; ограничение/управляемая остановка/запрет пуска по FSM+UPS-политике **без ослабления Nano**. Неопределённость — консервативно.
- Nano **не зависит** от этого сигнала для базовой отсечки. NC/fail-safe при пропадании сети/UPS подтверждается схемой и `safety-reviewer`.

## Протокол ошибок (сводка)

- Единый протокол, уровни severity (CRITICAL/HIGH/MEDIUM/LOW), авария => сохранение кода в NVM до/при fail-safe в обоих модулях. Детали протокола ошибок — при проработке (отдельный документ планируется); определения/миграция — `include/common_protocol.h` с `safety-reviewer`.
- CRITICAL: немедленная отсечка Nano/safe state. HIGH: защитные действия, возможный supervised reboot/power-cycle (только Nano, SR-B6), safe state при невосстановлении.

## Важные замечания

- **Nano — независимый Safety Unit, не заменяется.** KC868 — Main Unit **условно** (safety-gated).
- **KC868 onboard реле/PCF8574/I2C — не safety path.** I2C fault живёт отдельно от «живого» heartbeat (SR-B8); health в heartbeat (SR-B12).
- **Hardware paths:** heater series cutoff (SR-B4), pump transfer block/stop (SR-B18), safety-gates, ignition blocking — силовые/независимые.
- **220 В монтаж/изоляция/транзиенты (S-48):** DIN вне отсека котла, IP/clearance/creepage, подавление транзиентов (варистор/snubber/RC) согласовано с предохранителями/MCB/RCD type A 30 mA. Номиналы подтверждаются схемой.
- **Grounding/isolation architecture (§7.18)** — выбрать до схемы (A/B), не смешивать барьеры; фиксировать в pinmap/схеме.
- **`safety-reviewer`** — обязательный ревью **всех** правок кода в `src_esp32/`, `src_avr8/`, `include/` (особенно `common_protocol.h`), протокола, конфигурации, пин-мапа/силовой логики.
