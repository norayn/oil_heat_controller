# Протокол обмена ESP32 <-> Arduino Nano

Статус: **черновик**. Базовый вариант — **выделенный point-to-point UART**. Альтернатива (общая шина RS485) рассмотрена, но для safety-критичного канала **не рекомендуется** (см. `docs/architecture/modules.md`, раздел «Анализ UART vs RS485 для связи ESP32 <-> Nano»). Будет доработан при проектировании (шаг 1–2). `include/common_protocol.h` — отправная точка.

## Параметры связи
- **Интерфейс (базовый):** выделенный UART (точка-точка)
- **ESP32:** `Serial`/`Serial2` (точный выбор определится при пин-мапе)
- **Arduino Nano:** `Serial` (SoftwareSerial не приветствуется для критичного обмена)
- **Скорости:** ESP32 115200, Arduino 9600 (как в текущих заготовках) — при необходимости пересмотреть с обоснованием
- **Гальваноразвязка:** рассматривается (оптопары). Решение зафиксировать при схеме.
- **Примечание по RS485:** рассматривается использование уже заложенной шины RS485 для связи модулей. При **любом** выбранном транспорте требования heartbeat, таймаутов, CRC, fail-safe, детерминизма и изоляции отказов остаются **обязательными**. Использование **общей** шины RS485 для safety-связи допускается только при отдельном обосновании, доказательстве fail-safe при всех отказах шины/устройств и обязательном ревью `safety-reviewer`.

## Принципы
- **Простота и предсказуемость** — минимальный протокол, легко валидировать
- **Heartbeat** — обязательный, периодический обмен для детекта потери связи
- **Fail-safe** — при таймауте/ошибке CRC/неверном пакете/неопределённости Safety Unit переходит в безопасное состояние (включая safety-gate клапаны)
- **Односторонний приоритет защиты** — Safety Unit может послать аварийное сообщение и заблокировать/перевести горелку в безопасное состояние независимо от ESP32
- **Изоляция от RS485 доп.устройств** — safety-канал не должен зависеть от трафика/состояния RS485-устройств (заслонка, насосы полов и т.п.)
- **Версионирование** — добавить `protoVer` при первой рабочей версии
